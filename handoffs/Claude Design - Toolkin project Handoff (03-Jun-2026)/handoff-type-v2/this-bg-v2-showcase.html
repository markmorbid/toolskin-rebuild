--ts-this-bg · v2

Drop-in replacement for the v1 surface engine. Fixes the --ts-this-bg-focus purple bug (caused by color-mix(in oklch, …) wrapping hue through magenta when mixing a blue-tinted neutral with the orange accent), and extends the system with full state coverage, three border weights, semantic tints, and a parametric gradient library (linear · radial · mesh · conic · sheen · glass · veil).

1 · The focus fix

v1 mixes in oklch, which interpolates the hue ring. Between a blue-shifted dark (h ≈ 274°) and orange accent (h ≈ 39°) the short arc passes through magenta. v2 mixes in oklab using a desaturated accent tint and a lower default percentage (8%). Result: subtle warm focus, no purple, on any base surface.

✗ v1 — oklch wash, 20%
color-mix(in oklch, --ts-this-bg, --ts-accent 20%)
→ hue wraps via magenta → reads as purple
✓ v2 — oklab tint, 8%
color-mix(in oklab, --ts-this-bg, --ts-tone-accent-tint 8%)
→ no hue path, reads as a warm focus tint
✗ v1 on bg-1
✓ v2 on bg-1

2 · Surface scale · states · borders

Every token is recomputed from whichever --ts-this-bg is in scope. These three contexts each set a different base; identical token names produce surface-appropriate results.

Context A · --ts-this-bg = bg-1

oklch(20.92% 0.00611 271.12)

Context B · --ts-this-bg = bg-3

oklch(28.19% 0.00924 276.79)

Context C · --ts-this-bg = accent (chromatic surface)

oklch(67.59% 0.21747 38.80)

3 · Gradient library

Linear · radial · mesh · conic · sheen · glass · veil. Every gradient derives from --ts-this-bg and the tokenized stops / angle / mix-percent. Tune --ts-grad-angle, --ts-grad-mix-perc, or --ts-grad-pos-* on any scope to retune the whole family.

BG family — surface-only

ACCENT family — brand-true

MIX family — bg + accent through oklab (never purple)
