Toolskin Design System · Refactor

Type Scale v2 — single-source modular system

A ground-up replacement for the legacy “harmonic” scale, whose single-ratio promise was decorative — the steps hardcoded a different ratio, comments contradicted their own values, and --ts-fs-h3 shipped an inverted clamp that silently pinned to its minimum. v2 is honest: two zones, each with the right job. A px-snapped UI ladder (10–20px) for functional text, and a true Major-Third display ladder (24px+) for headings. One knob — --ts-type-scale — rescales everything, and every value is rem-based so browser zoom still works.

01 The engine

One base unit (--ts-fs, the body size) and one documented display ratio (--ts-ratio-display). The UI ladder is px-snapped for crispness; the display ladder is computed on a constant 1.25, fluid via clamp() with every bound verified min < max.

The source of truth

/* one base, one knob, rem-based */
--ts-fs-root:    16px;   /* browser default */
--ts-type-scale: 1;      /* density knob */
--ts-fs: calc(0.9375rem * var(--ts-type-scale)); /* 15px body */

/* UI zone — px-snapped rem fractions */
--ts-fs-sm: calc(0.875rem * var(--ts-type-scale));
--ts-fs-md: var(--ts-fs);
--ts-fs-lg: calc(1.0625rem * var(--ts-type-scale));

/* display zone — true Major Third, fluid */
--ts-ratio-display: 1.25;
--ts-fs-3xl: clamp(1.5rem, …, 1.875rem); /* 24→30 */
--ts-fs-4xl: clamp(1.875rem, …, 2.375rem); /* 30→38 */

05 Flex & content-aware heroes

The fixed ladder caps at 76px (--ts-fs-display-xl). When a hero must fill its area at any aspect ratio, switch methods. Two are provided — pick by what the type should track.

Viewport-fill · vw + vh + vmin

/* tracks the viewport AREA at any ratio */
--ts-fs-flex-hero: clamp(
  2.75rem,                  /* floor */
  calc(4vw + 4vh + 2vmin),  /* fill */
  8.5rem);                  /* ceiling */

/* vw over-grows wide, vh over-grows tall;
   vmin corrects the diagonal. Scalars sum
   to a "fill budget" — always clamp(). */

07 What v2 fixes

Every defect in the legacy scale, and how the refactor resolves it. All public token names are preserved — v2 is a drop-in: load it after toolskin.css.

1

Double-declared base

--ts-fs-base: 0.8rem was immediately overwritten by 13px. v2 has one base, --ts-fs, which every token derives from.

2

Decorative ratio

--ts-fs-ratio: 1.12 was never used — steps hardcoded powers of 1.125 plus ad-hoc multipliers. v2's display ladder is computed on a real, constant --ts-ratio-display: 1.25.

3

Lying comments

--ts-fs-sm was labelled ~11.6px but resolved to 12.1px; --ts-fs-md said 13px while its own alias said 14.6px. v2 comments are verified against computed values.

4

Inverted clamp

--ts-fs-h3: clamp(xl, 2vw, lg) had a max (~14.6px) smaller than its min (~18.5px), silently pinning to the min forever. v2: --ts-fs-h3 → --ts-fs-2xl, a valid 20→24px clamp.

5

Duplicate & magic values

--ts-fs-lead was declared twice with conflicting comments; display steps used magic numbers (3.247, 4.328…). v2 has one declaration per token, all on the 1.25 ladder.
