## RULING 7 engine readiness (Task 5 input)

### Sub-floor ΔL targets
Two surfaces in the recommended-default `dark-practical-neutral-v1` preset:
- `--ts-bg-body` → `oklch(15.88% …)`
- `--ts-bg-0` → `oklch(18.20% …)`

That is **ΔL ≈ 2.32 percentage points** between `body` and `bg-0`. The `--ts-this-bg-dark` formula (`surfaces.css` L82) recesses `--ts-this-bg` toward `--ts-tone-floor` (= L of `--ts-bg-body`) by `--ts-this-bg-grad-dark-pct: 14%`. On `bg-0` (L=18.2) recessing toward floor (L=15.88), 14% recession yields **L ≈ 17.87** — barely 0.33 points darker than the starting surface. **That is below visual perception** and is exactly the degeneracy the prior agent reported as "gradDarkPct = 100% on dark presets."

**Recommended sub-floor ΔL targets (per theme, applied to the recession amount):**
- Dark preset family: minimum **ΔL ≥ 3.0** between any consumer surface and its `-dark` step (because user pupils are dilated; visible recession needs more)
- Light preset family: minimum **ΔL ≥ 4.0** between any consumer surface and its `-dark` step

The fix is **NOT** to push `--ts-this-bg-grad-dark-pct` to 100% (which collapses to the floor and loses the gradient). The fix is to **change the mix target** when the consumer surface is already near the floor.

### APCA Lc targets (confirm)
Per the architect's own engine inspection of `generate-colors.js` L32: current `APCA_TARGET = { primary: 75, secondary: 45, muted: 25 }`. These are **CALIBRATED FLOORS** for the pre-runtime-tuner curated bases (Option 4 ruling). Prior council guidance of **Lc 15 / Lc 30** likely referred to **derivative-state contrast** (e.g., hover-vs-base) — those are NOT yet measured. Recommend:
- **Lc 15 minimum** for `--ts-this-bg-hover` vs `--ts-this-bg` (state perceivability)
- **Lc 30 minimum** for `--ts-this-bg-border` vs `--ts-this-bg` (resting-edge visibility — the rebuild dev already tuned 10%→20% by eye because Lc<15 was invisible per surfaces.css L57 comment)

### Per-preset vs per-theme bake (Pattern-16 Option B)
**Per-preset.** Each of the 10 surface presets has different lightness ramps and chroma profiles. A single per-theme bake will fail on Classic Cool vs Practical Neutral. The bake should iterate `ALL_PRESETS` in `generate-colors.js` and emit a derivative-knob block scoped to `.ts-preset-{id}` for each.

### Path-A boundary (when runtime apcach takes over)
**Build-time** apcach in `generate-colors.js` handles:
- Primitive APCA verification (already done L274-287)
- Per-preset derivative-knob bake (NEW — what Task 5 produces)
- Status color generation + on-status auto-ink (NEW — see Gap 5)

**Runtime** apcach (loaded as a library at page execution) handles:
- User-modified `--ts-accent` (sliders, theme picker) where the auto-derivatives must recompute live
- Custom-preset additions outside the curated 10

**Boundary:** if it can be known at build time (the 10 curated presets, the brand `--ts-accent: #ff5500`), bake it. Only the user-customizable surface gets runtime apcach.

### Math degeneracy fix (the `gradDarkPct=100%` problem)
The bug: when `--ts-this-bg` ≈ `--ts-tone-floor` (consumer surface near body floor), mixing toward floor at any percentage <100 produces a step too small to see, and at 100% collapses to the floor identically.

**Fix — adaptive mix target via OKLCH lightness probe:**

```css
/* Replace the simple recession in surfaces.css L82 */
--ts-this-bg-dark: color-mix(
  in oklch,
  var(--ts-this-bg),
  /* If consumer is already dark, recess toward pure black (L=0).
     If consumer is light, recess toward floor. The relative-color
     calc below interpolates between the two targets based on the
     consumer's own lightness. */
  oklch(from var(--ts-this-bg) calc(l - 6) 0 0)
  100%
);
```

This **always produces ΔL ≈ 6** regardless of where the consumer sits in the ramp. The `--ts-this-bg-grad-dark-pct` knob is retired in favor of an absolute ΔL constant baked per theme:

```css
:root { --ts-this-bg-delta-l-dark: 6;  --ts-this-bg-delta-l-bright: 4; }
[data-theme="light"] { --ts-this-bg-delta-l-dark: 8;  --ts-this-bg-delta-l-bright: 5; }
```

(values illustrative — Task 5 baker computes the per-preset minimum that achieves Lc-15 state distinguishability against the surface's own ink color)

This is **Pattern-16 Option B** done correctly: the engine knows the target ΔL, the math is theme-aware, the consumer doesn't have to know which preset is loaded.

## Critical gap §1 — Skill template vs Rebuild architecture

**The skill's `expert-designer/templates/tokens.css` is the WRONG architecture** in three places:
1. **L30-32 declares `--ts-accent-h/-s/-l` (HSL channels) and L34 builds `--ts-accent` via `hsl()`** — RULING 1 + RULING 7 say accent is OKLCH-baked via apcach. Rebuild `primitives/colors.css` L13-14 is correct: `--ts-accent: oklch(67.59% 0.21747 38.80);` with hex fallback.

For Toolskin Rebuild, components MUST `<link>` the rebuild's `primitives/colors.css` + `system/{surfaces,text,spacing,shape,motion,accent}.css` and **never** load `expert-designer/templates/tokens.css`. The skill needs a Toolskin-Rebuild-specific template that re-exports only the **type/space/shape/motion** blocks (lines 53-152 of the current template) — color/surfaces come exclusively from `assets/css/next/`. **The rebuild primitives win.**

## Critical gap §2 — Hand-tuned literals in `surfaces.css` violate RULING 7

`surfaces.css` lines 48-60 declare:
```css
--ts-this-bg-grad-bright-pct: 6%;
--ts-this-bg-grad-dark-pct:   14%;
--ts-mix-perc:          20%;   /* tuned UP from spec's 10% by eye */
--ts-mix-perc-hover:    40%;
--ts-mix-perc-active:   34%;
--ts-mix-perc-disabled: 10%;
```

These are **hand-tuned literals where RULING 7 demands engine-derived values.** The author's own comment on L55-56 admits the spec values produced invisible borders. **This is exactly Pattern-16:** when the spec math degenerates, hand-tuning is a stopgap *until the engine is upgraded*, not a permanent solution.

**Task 5 must replace these.** The replacement is the per-preset bake described in §RULING 7 above: `generate-colors.js` iterates the 10 presets, computes the minimum mix percentage per derivative slot that achieves the target APCA Lc (15 for state, 30 for borders), and emits per-preset overrides:

```css
.ts-preset-dark-practical-neutral-v1 {
  --ts-mix-perc:          22%;  /* baked: yields Lc 30.4 border on bg-2 */
  --ts-mix-perc-hover:    38%;
  --ts-mix-perc-active:   31%;
  --ts-mix-perc-disabled: 9%;
  --ts-this-bg-grad-bright-pct: 6%;
  --ts-this-bg-grad-dark-pct:  /* derived per surface, see math-degeneracy fix */;
}
```

The `:root` defaults in `surfaces.css` become **fallback values** for un-keyed presets only; every shipping preset gets its own bake.

## Architect verdict
